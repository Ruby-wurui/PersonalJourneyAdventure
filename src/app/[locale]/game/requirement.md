# 产品名称（暂定）：**Neon Claw / 霓虹神手**

## 1. 产品概述 (Product Overview)

**核心概念：** 这是一个基于Web浏览器的3D 仿真抓娃娃游戏。仅通过**摄像头**捕捉手部动作来控制虚拟娃娃机的机械爪，完成移动、下抓、抓取和松开的动作(也可以用鼠标或键盘)。

**目标用户：** 喜欢尝试新奇Web技术的极客、休闲游戏玩家、需要互动营销活动的品牌方。

**核心体验：** “所见即所得”的操控感 + 真实的物理碰撞反馈。

---

## 2. 游戏设定与世界观 (Game Setting)

为了配合“高科技手势控制”的调性，我们不采用传统的粉色可爱风，而是推荐**赛博朋克。

- **视觉风格：** 暗色背景，高亮的霓虹灯条（粉色、青色），电子故障（Glitch）艺术效果。
    
- **抓取物：** 毛绒玩具，可以是“比特像素块”、“发光的能量球”或“复古电子元件”。
    
- **音效：** 电子合成器音乐（Synthwave），机械爪移动时的伺服马达声，抓取成功的8-bit金币声。
    

---

## 3. 核心玩法与手势交互 (Core Gameplay & Interaction)

这是产品的核心壁垒。我们需要定义一套简单、直观且低延迟的手势指令。建议使用 **MediaPipe Hands** 或 **TensorFlow.js** 方案。

### 3.1 手势映射规则 (Gesture Mapping)

我们定义三种主要状态：

1. **待机/瞄准状态 (Hovering):**
    
    - **手势：** **五指张开 (Open Palm)**。
        
    - **游戏反馈：** 屏幕上会出现一个半透明的“手掌光标”或直接控制机械爪的影子。
        
    - **逻辑：** 手掌在摄像头画面中的 X/Y 轴移动 = 机械爪在游戏平面上的 X/Z 轴移动。
        
2. **下爪/抓取 (Grab):**
    
    - **手势：** **握拳 (Fist)**。
        
    - **游戏反馈：** 机械爪立刻垂直下落。一旦触碰到物体或到达底部，爪子闭合。
        
    - **逻辑：** 触发 `Drop` -> `Close Claw` 动画。
        
3. **移动至出口/松开 (Release):**
    
    - **手势：** 保持握拳移动到出口上方，然后**再次张开五指**。
        
    - **游戏反馈：** 爪子松开，物品受重力掉落。
        

### 3.2 游戏流程 (Game Loop)

1. **授权阶段：** 用户进入网页 -> 浏览器请求摄像头权限 -> 用户允许。
    
2. **校准阶段：** 屏幕提示“请举起你的手” -> 系统识别出手部骨架 -> 显示“校准成功”。
    
3. **游戏开始：** 倒计时30秒。
    
4. **操作阶段：** 用户移动手掌定位 -> 握拳下抓 -> 运送 -> 松开。
    
5. **结算阶段：**
    
    - _成功：_ 物品落入洞口 -> 播放特效 -> 积分+1。
        
    - _失败：_ 抓空或中途掉落 -> 提示“再试一次”。

## 4. UI 设计与原型描述 (UI/UX Design)

Web端界面分为三个层级。


### 4.1 背景层 (The Machine)

- **主画面：** 一个3D视角的娃娃机内部。
    
- **物理元素：** 堆叠的奖品、机械爪（带悬挂绳索）、出口洞（通常在左下角或右下角）。
    
- **光照：** 动态光源，随着爪子移动而改变阴影。
    

### 4.2 视频反馈层 (The Mirror)

为了让用户知道自己的手在哪里，必须有一个摄像头反馈窗口。

- **位置：** 建议置于屏幕右下角（画中画模式），或者以**低透明度全屏覆盖**在背景层之上（类似镜子）。
    
- **增强现实 (AR) 元素：** 在用户的视频流上，绘制出绿色的手部骨架连接线（Skeleton），让用户确认系统识别到了他的手。
    

### 4.3 HUD 信息层 (Heads-Up Display)

- **顶部居中：** 倒计时计时器（样式：`00:25`，红色数字）。
    
- **右上角：** 当前积分/抓到的物品数。
    
- **屏幕中央提示：** 动态文字提示（如：“张开手掌移动”、“握拳抓取！”）。
    
- **状态指示灯：**
    
    - 🟢 **Ready** (识别到手)
        
    - 🔴 **Lost** (手移出画面/未识别)

## 5. 技术架构建议 (Technical Stack)

为了实现这个Web游戏，推荐以下技术栈：

- **前端框架：** React 或 Vue 3 (用于管理UI状态)。
    
- **3D/游戏引擎：**
    
    - **Three.js / React-Three-Fiber:** 最适合做轻量级3D Web游戏。
        
    - **Cannon.js:** 物理引擎，处理娃娃的重力、碰撞、摩擦力（这是抓娃娃机手感的关键）。
        
- **手势识别 (核心)：**
    
    - **MediaPipe Hands (by Google):** 性能极佳，Web端运行流畅，能精准识别手掌开合。
        
- **状态管理：** XState (非常适合管理游戏状态机：待机->移动->下抓->返回)。

## 6. 关键难点与解决方案 (Challenges)

1. **Z轴深度问题：**
    
    - _问题：_ 摄像头是2D平面（X, Y），但娃娃机是3D的（需要控制前后深度 Z）。

            
        - **方案B：** 映射手掌在画面中的上下位置 = 娃娃机的进出（Z轴）；映射手掌的左右 = 娃娃机的左右（X轴）。
            
2. **长时间举手的疲劳感：**

    - _方案：_ 将单局游戏时间严格限制在 30-45 秒内。
        
3. **误触问题：**
    
    - _方案：_ 增加“握拳确认”的防抖逻辑（例如：连续检测到5帧握拳才触发下爪），防止手指轻微弯曲导致误判。

### 2.2 核心循环 (Core Loop)

1. **瞄准 (Positioning)：** 控制爪子左右移动。爪子带有惯性，不会瞬间停下。
    
2. **下爪 (Dropping)：** 触发下抓指令，爪子张开并自动下落（或手动控制Z轴深度，视难度设定）。
    
3. **抓取 (Grabbing)：** 爪子闭合。利用物理摩擦力和合力尝试夹住物体。
    
4. **运送 (Transporting)：** 爪子自动或手动提回到顶部，并移向出口。
    
5. **松开 (Releasing)：** 爪子张开，物体受重力掉落。若落入出口区域，得分。
    

### 2.3 物理设计 (Physics Design) - **关键修正**

基于 Matter.js 的验证结论，物理系统需遵循以下规则：

- **爪子移动逻辑：**
    
    - ** 基于速度的力学控制 (`setVelocity` + Speed Clamping)。
        
    - **逻辑：** 计算目标距离 -> 施加指向目标的速度 -> 限制最大速度 -> 物理引擎计算碰撞。
        
- **爪子结构：**
    
    - **底座：** 有质量的刚体，锁定旋转
        
    - **手指：** 通过铰链关节 (`Constraint`) 连接到底座。
        
    - **肌肉：** 动态弹簧。抓取时 `Length` 变短且 `Stiffness` 变大；松开时反之。
        
- **奖品设计 (The Chaos Factor)：**
    
    - 包含：六边形、T型块（类似俄罗斯方块）、胶囊型。这些形状会产生不可预测的堆叠和滑落，增加“赌博感”。

## 7. 风险规避 (Risk Mitigation)

|**风险点**|**解决方案**|
|---|---|
|**穿模/物理爆炸**|严格限制爪子最大速度 (`MAX_SPEED`)；增加物体密度；避免强制设置位置。|
|**手势识别延迟**|CV 逻辑放入 WebWorker；UI 层预测渲染；使用简单的骨架模型。|
|**游戏太难/抓不起**|动态难度调整：如果连续3次抓空，临时增加爪子摩擦力或指尖抓力。|
|**游戏太简单**|引入圆形的、表面光滑的物体；设置不规则的碰撞体；减少倒计时时间。|

#### 1. 产品概述 (Executive Summary)

**核心变动：** 从“硬核仿真”转变为“带有物理反馈的赌场/街机游戏”。 **一句话描述：** 一款拥有赛博朋克视觉冲击力、结合轻量级 AI 手势互动、以“集齐图鉴”为驱动力的 Web 端解压游戏。

#### 2. 游戏机制：从“仿真”到“表演” (The "Fake It" Mechanics)

这是最大的修正点。我们不再信任 Matter.js 去处理精细的摩擦力，那太不可控了。

**2.1 “磁吸”抓取逻辑 (The Magnetic Claw)**
- **逻辑 (Raycast + Snap)：**
    
    1. **判定：** 当爪子下落接触物体时，后端/逻辑层直接根据概率表（Loot Table）判定本次抓取是否成功。
        
    2. **成功 (Win State)：** 爪子并不真的去“夹”，而是生成一个隐形的强力关节 (Constraint)，直接把物体“粘”在爪子中心。播放“夹紧”动画。
        
    3. **失败 (Lose State)：** 爪子假装夹起物体，上升到一半时，程序强制断开连接，模拟“滑脱”效果。
        
    
    - **专家点评：** 这就是街机厅娃娃机的真实逻辑。**玩家以为是物理失误，其实是概率控制。**这保证了开发者对“出货率”的绝对掌控。
        

**2.2 物理仅作“调味剂” (Physics for Juice)**

- **保留 Matter.js 的地方：** 奖品池里的物体碰撞、掉落时的翻滚、撞击墙壁的反弹。这些需要物理引擎来提供视觉上的混乱美感。
    
- **剔除 Matter.js 的地方：** 爪子的抓力计算、物体与爪子的摩擦计算。
    

**2.3 视觉反馈 (The "Juice")**

- **撞击感：** 爪子碰到物体堆时，整个屏幕轻微震动 (Screen Shake)。
    
- **光效：** 抓取成功的瞬间，爪子爆发霓虹光圈；物体被提起时拖着长长的光尾（Trail）。
    
  充能（决定下爪速度/冲击力）。
    

**3.2 辅助操作：AI 手势暴击 (The "Magic Hand")**

    
- **手势 = 大招 (Power-up)：** 当能量条满时

    - **打响指 (Snap)：** 震碎画面上的杂物，重置奖品堆叠位置（解决死角问题）。
        
    - **比“V”字：** 下一次抓取变为“绝对必中爪”（100% 概率）。
        
- **专家点评：** 这种短时间（3-5秒）的手势交互既保留了 AI 的酷炫感，又完全规避了疲劳感和延迟造成的挫败感。
    

#### 4. 经济与奖励系统 (The Meta Game)

这是解决“为什么玩”的关键。将“抓方块”变成“开盲盒”。

**4.1 奖品池设计 (The Capsules)**

- 不要直接抓 T 型块或六边形。
    
- **所有奖品统一为“胶囊/扭蛋” (Capsules)：** 圆形刚体，物理性能最稳定，最不容易穿模。
    
- **内容物差异：** 胶囊内部贴图不同（普通、稀有、史诗）。
    

**4.2 收集系统 (Collection Album)**

- **图鉴：** 抓到胶囊后，弹窗显示“你获得了 [赛博猫咪碎片 1/4]”。
    
- **合成：** 只有集齐碎片，才能解锁一张完整的精美壁纸、NFT、或者商户优惠券。
    
- **视觉奖励：** 随着分数增加，背景的赛博朋克城市会从“贫民窟”升级为“霓虹摩天楼”。
    

#### 5. 技术修正 (Technical Adjustments)

为了配合新方案，技术栈微调：

    
- **渲染：** 推荐 **Pixi.js**。你需要大量的粒子特效（光尾、爆炸、火花）来掩盖“物理作弊”的痕迹，Pixi 在 2D 粒子渲染上性能最强。
    
- **逻辑层：** 必须引入**伪随机算法 (Pseudo-Random Distribution)**。不能让玩家连续 10 次抓不到，也不能连续 10 次抓到。设计一个“保底机制”（例如：第 5 次必定抓起）。
    


- **风险：** 玩家发现是“假物理”怎么办？
    
    - **对策：** 在“滑脱”动画上下功夫。让物体在爪子上摇摇欲坠再掉下去，做得足够戏剧化，玩家只会怪自己运气不好，不会怪物理引擎。
        
- **风险：** 游戏流程太短。
    
    - **对策：** 引入“狂热模式 (Fever Mode)”。背景音乐加速，爪子速度变快，所有抓取判定临时变为 100% 成功率，持续 10 秒。这是现代休闲游戏的标配。
